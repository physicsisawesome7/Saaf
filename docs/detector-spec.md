# Detector spec and conformance format

The single source of truth for detection is [`spec/entities.json`](../spec/entities.json), validated by [`spec/schema/entities.schema.json`](../spec/schema/entities.schema.json). Ports load copies generated by `python scripts/sync_spec.py`. CI runs `--check` to fail on drift.

## Entity fields

| Field | Type | Meaning |
|---|---|---|
| `id` | `UPPER_SNAKE` | Stable identifier, used in tokens (`[PAN_1]`) and policy. Renaming it is a breaking change. |
| `label`, `phase`, `severity` | string | Documentation; `severity` ∈ low/medium/high/critical. |
| `priority` | int | Tie-breaker in overlap resolution (higher wins at equal score). |
| `canonical` | `digits` / `alnum_upper` / `lower` / `strip` | Form passed to validators and used for vault deduplication. |
| `patterns[]` | `{pattern, flags?, group?}` | Regexes compatible with both Python `re` (+`re.ASCII`) and JS `RegExp`. `flags: "i"` for case-insensitive; `group` selects a capture group as the span. |
| `validator` | name | One of the named validators. |
| `on_invalid` | `drop` / `base` | What to do when the validator fails. |
| `base_score`, `validated_score` | 0–1 | Score before context. |
| `requires_context` | bool | Drop unless a `context` keyword is nearby. |
| `context[]`, `context_boost` | | Positive keywords (ASCII ones need word boundaries; Indic script ones match as substrings). |
| `negative_context`, `negative_penalty` | list or `@set` | Keywords that lower the score when they are the nearest label within the same clause. |
| `ocr` | `{pattern, shape, min_digits, score}` | Looser regex + D/L shape for checksum-assisted OCR repair. |
| `fake` | name | Generator for format-preserving fake tokens. |

## Writing portable patterns

- Use `[0-9]`, never `\d` (Unicode digits in Python), and `[A-Za-z]`, never `\w`.
- Use lookbehind/lookahead for boundaries, never `\b`.
- No named groups (the syntax differs), no possessive quantifiers, no atomic groups.
- Avoid nested quantifiers over overlapping classes (catastrophic backtracking).

## Adding an entity (checklist)

1. Add it to `spec/entities.json`; run `python scripts/sync_spec.py`.
2. If you need a validator, implement it in **both** `validators.py` and `validators.ts`.
3. Add vectors: ≥3 to `validators.jsonl` (valid, invalid, edge case) and ≥3 to `detect.jsonl` (positive, hard negative, messy format).
4. Run both test suites and the benchmark; paste the deltas into the PR.
5. Update `docs/limitations.md` if the entity is context-gated.

## Conformance vector files

`spec/conformance/validators.jsonl`
```json
{"validator": "gstin", "input": "27ABCPE1234F1ZB", "expect": true, "note": "optional"}
```

`spec/conformance/detect.jsonl`. `expect` is the **exact** ordered list of findings at the default threshold, so an extra finding fails the test.
```json
{"id": "aadhaar-spaced", "text": "My Aadhaar is 2345 6789 0124.", "expect": [{"entity": "AADHAAR", "text": "2345 6789 0124"}]}
```

`spec/conformance/restore.jsonl`
```json
{"id": "lowercase", "vault": {"[AADHAAR_1]": "2345 6789 0124"}, "input": "it is [aadhaar_1]", "expect": "it is 2345 6789 0124", "unknown": []}
```

Offsets are not compared, because Python counts code points and JavaScript counts UTF-16 units. Matched text is compared instead.

**All identifiers in vectors must be synthetic.** Generate valid ones with `saaf validate` and the helpers in `saaf.validators` (`verhoeff_check_digit`, `gstin_check_char`).
