Install and deploy

One command brings up the whole stack on one machine. The same code scales out to separate databases, vector stores and model servers.

What runs

  • smriti-api: the web app and API. Stateless; run several processes.
  • smriti-worker: ingestion jobs and scheduled crawls.
  • PostgreSQL: documents, versions, conversations and the audit log.
  • Qdrant: dense and sparse vectors.
  • Embeddings and reranker: served by Text Embeddings Inference.
  • LLM: vLLM serving an AWQ model with prefix caching. Optional.
  • Sandbox: an isolated service for agents' Python, on an internal-only network.

Hardware profiles

cpunonenone: verified extractive answersCPU
gpu-6gb6 GB laptop cardsQwen3-4B AWQCPU

gpu-16gb16 GBQwen3-8B AWQGPU

Each profile file shows its memory arithmetic. Force one with ./install.sh --profile gpu-12gb --reconfigure. The default models, embeddings and reranker are Apache-2.0. The 12 and 16 GB profiles are sized from documented arithmetic and should be benchmarked on your card.

Why it is cheap to run

  • Lookups and table questions are answered by verified quotes or by code, without the model.
  • A guarded cache reuses verified answers for people with identical access.
  • Evidence is compressed to the relevant sentences, under a token cap.
  • Prompts open with a fixed prefix that the model server caches.
  • Admission control serves the verified extract instead of queueing when the GPU is saturated.

Measure on your hardware with smriti bench --concurrency 8 --requests 200 (add --no-cache for the GPU path only). Prometheus metrics are at /api/metrics.

Configuration

Everything is set in .env. Common changes:

ChangeHow
A different modelLLM_MODEL=…, then restart the llm service
A model on another machine, Ollama or llama.cppSMRITI_CHAT_URL and SMRITI_CHAT_MODEL pointing at any OpenAI-compatible endpoint
Serve your networkSMRITI_BIND=0.0.0.0 behind a TLS reverse proxy
Real loginsSMRITI_AUTH=token with SMRITI_API_TOKENS, behind your SSO proxy
More API processesSMRITI_WORKERS=4
Public address for bots and webhooksSMRITI_PUBLIC_URL=https://smriti.example
Web search for agentsadd search to COMPOSE_PROFILES and set SMRITI_SEARXNG_URL
Turn code execution offSMRITI_SANDBOX_URL= (empty)

Your own documents and roles

Each organisation is a pack: a folder of YAML and Markdown for documents, roles, sources, schemas, guardrails, glossary and skills. Copy the demo pack, edit it, and point SMRITI_PACKS at it. Check a pack without starting anything:

smriti validate-pack packs/tenants/your-org

Scaling out

API processes are stateless, and ingestion jobs are database rows that any number of workers claim atomically. For production, use PostgreSQL (SMRITI_DATABASE_URL), Qdrant (SMRITI_VECTOR_BACKEND=qdrant) and S3-compatible storage (SMRITI_BLOB_URL=s3://…).

Offline installs

Run the installer once online so the model cache fills, then set HF_HUB_OFFLINE=1. Move container images with docker save and docker load. After that, nothing needs the internet.

Troubleshooting

  • Containers can't see the GPU: install the NVIDIA Container Toolkit on Linux, or update the driver and Docker Desktop (WSL2 backend) on Windows.
  • The model server runs out of memory: lower LLM_MAX_NUM_SEQS or LLM_MAX_MODEL_LEN, or LLM_GPU_MEMORY_UTILIZATION by 0.05.
  • Newest GPUs without matching kernels: set VLLM_IMAGE to a build that supports your card.
