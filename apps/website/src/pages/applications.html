Applications

One memory, wherever people work.

Smriti's agents and workflows run in its own web app, inside your website, in chat apps and in your code. Wherever they run, the same rule applies: the answer is checked, and it never shows more than the person behind it may see.

Where it runs

Seven ways in.

Integration docs →
◎

Web app

Ask with evidence and a trace, build agents and workflows, browse versions and diffs, approve drafts, check the audit chain.

◱

Website widget

One script tag adds a chat bubble with streamed, cited answers. It runs only on sites you allow, as you or as the signed-in user.

#

Slack

Mention the app or message it. Answers arrive in the thread, approvals are buttons only the asker can press.

✈

Telegram

A bot for staff in the field. Each chat continues one conversation, with personal data masked in replies.

◆

Discord

An app with an /ask command, with every request verified by Discord's signature.

{}

OpenAI-compatible API

Point any SDK or chat client at /v1/chat/completions and choose an agent as the model.

⇄

MCP server

Let assistants such as Claude or IDE agents search Smriti, with the caller's permissions fixed when it starts.

✓

Same rules everywhere

Every surface states who it answers as. Chat-app replies are masked, and answers citing confidential documents stay in Smriti.
