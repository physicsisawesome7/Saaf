Workflows

Draw the process. Keep the guarantees.

Some work is more than one question. A workflow chains agents, conditions, variables, code and human sign-off into one run on a visual canvas. Every agent step still acts as the person running it, cites its sources and masks personal data.

Building blocks

Nine steps, connected on a canvas.

◎

AI agent

A classic, agentic or research agent on a templated prompt, with its own tools. Its cited answer goes into a variable.

⑂

If / else

Conditions checked in order; the first true one wins, otherwise the else branch.

≔

Set state

Variables from expressions such as float(amount) * 0.05, without calling a model.

{}

Code

Python in a sandbox with no network. It reads the workflow's variables and prints a value back.

✋

Human approval

Pauses until the person running it approves or declines, and branches on the answer.

↻

Loop

One agent prompt for each item in a list, with the answers collected and their citations merged.

Plus Start, End (renders the final answer from a template) and Note (a comment on the canvas).

Variables and expressions

Logic without a scripting engine.

Prompts and outputs are templates with {{ }}. Conditions use a small expression language that Smriti parses itself. Attribute access, imports and unknown functions are rejected when you save, so a workflow can't reach anything it shouldn't.

len(answer) > 0 and contains(answer, 'clause')
float(amount) * 0.05
[strip(q) for q in split(query, ';')]
join(pluck(answers, 'answer'), '\n\n')
'urgent' if matches(lower(query), 'today|now') else 'normal'
Safe by construction

What still holds inside a workflow.

Acts as the runner

Every agent step searches only what the person running the workflow may see.

One citation list

Citations from every step are renumbered into one list, and the final answer is scored against them.

Approvals pause it all

A human step, or a tool action inside an agent step, pauses the whole run. Only the runner can approve.

Bounded and explained

A run stops after 50 steps. Any failure ends with an answer naming the step that failed, and why.

Validated before it can run

Saving checks the graph: one start, at least one end, every output connected, every step reachable, valid variable names and safe expressions. Errors read like "'If / else' (else) is not connected to a next step".
