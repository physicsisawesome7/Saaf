Knowledge and sources

Smriti's memory comes from sources you connect in the Ingest view. Each one has a test run, its own access and schedule settings, and background jobs you can watch and cancel.

Source types

KindWhat it reads
WebsiteA whole site from a start page, scoped by path or domain, with linked PDF, Office and ZIP files. Honours robots.txt and a per-host rate limit.
Web page or file linkOne URL. A re-sync stores a new version when it changes.
Upload filesDrag and drop, up to 200 MB each, ZIP archives unpacked. Parsed in the background.
REST / JSON APIRecords from an HTTP API, with auth, pagination and field mapping, or a linked file per record.
Database (SQL)One read-only query: each row a document, or the result as one table for exact totals.
MCP serverEvery resource on a server, or the result of one tool call.
RSS, Atom or sitemapEach linked page or document, with its title and date.
Server folderFiles under an allowed folder, such as a mounted shared drive.

Adding a source

  1. Add source: pick a kind, or start from a demo preset.
  2. Test connection: a dry run that finds a few items and parses the first ones. Nothing is stored.
  3. Save & run: queues a job for the worker.
  4. Jobs: live progress, a result for each item linked to the library, a log, and Cancel.

Re-runs are cheap: unchanged content is recognised by hash and skipped, changed content becomes a new version, and removed items are kept or marked removed.

Access and schedules

Every source sets the sensitivity, divisions, projects, need-to-know groups and document type of what it brings in, plus a cron schedule and what to do when an item disappears. If the same content arrives from two sources with different access, the stricter rule wins.

Watching for change

When a watched source changes, Smriti writes a "what changed" note and lists the documents that cite the changed text, filtered to what each reader may open.

Safety

  • Egress guard: every request and redirect is checked, blocking loopback, cloud-metadata and reserved addresses and Smriti's own internal services.
  • Credentials: encrypted at rest and never returned by the API.
  • SQL: a single SELECT, in a read-only transaction, with a row cap.
  • MCP: network transports only, so a source can't run programs on the host.
  • Audit: every create, change, run, preview and cancel is logged.
Scanned pages without a text layer are flagged as low-confidence and queued. OCR and advanced layout parsing are plug-in points, not bundled.
