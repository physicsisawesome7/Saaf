API, MCP and CLI

Everything in the web app is available over HTTP. Interactive OpenAPI docs are served by every installation at /api/docs.

Authentication

  • Demo mode uses the directory in the pack and a X-Smriti-User header. For local trials only.
  • Token mode (SMRITI_AUTH=token) maps bearer tokens in SMRITI_API_TOKENS to people, behind your SSO proxy.
  • Agent keys (sk-smriti-…) work only on that agent's chat endpoint and the OpenAI-compatible endpoint, and act as their creator.

Main endpoints

EndpointUse
POST /api/ask, /api/ask/streamAsk the memory, with citations, verification and an optional "as of" date.
GET /api/searchPermission-aware search without an answer.
GET /api/documents, /api/documents/{id}Documents, versions, diffs and access explanations.
GET/POST /api/connectors, POST /api/ingest/uploadSources and uploads; /api/jobs for progress.
GET /api/agents/catalogKinds, tools, workflow steps, templates and expression functions.
GET/POST/PUT/DELETE /api/agentsAgents and workflows.
POST /api/agents/{id}/chatRun an agent. Set stream for server-sent events.
POST /api/agents/previewRun an unsaved agent or workflow.
POST /api/runs/{id}/approveApprove or decline a paused action.
GET/POST /api/toolsConnected tools.
GET/POST /api/channelsWidget and chat integrations.
GET /api/metrics, /api/health?deep=1Prometheus metrics and readiness.

Streaming events

Streamed runs send these server-sent events: start (run and conversation ids), step (a retrieval, plan, tool call or workflow step), token (answer text), approval (paused until approved) and final (the verified answer, citations, steps and files).

OpenAI-compatible

from openai import OpenAI
client = OpenAI(base_url="https://smriti.example/v1", api_key="sk-smriti-…")
r = client.chat.completions.create(
    model="agent/contract-analyst",
    messages=[{"role": "user", "content": "What is the liability cap?"}],
)
print(r.choices[0].message.content)

Use the model smriti/<tenant> with a user token to ask the memory directly. The answer carries its sources.

MCP server

smriti mcp --as asha

Exposes search_knowledge, ask_question and get_document to an MCP client, with the caller's permissions fixed when it starts.
