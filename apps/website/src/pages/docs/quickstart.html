Quickstart

Run Smriti on your machine, open the demo organisation, and see verified answers, access control and versions at work. It takes about five minutes.

1. Install

You need Docker. A GPU is optional: without one, Smriti uses its CPU profile and answers with verified extracts.

git clone https://github.com/physicsisawesome7/smriti
cd smriti
./install.sh                                          # Linux, WSL2, macOS
powershell -ExecutionPolicy Bypass -File install.ps1  # Windows

The installer checks Docker and GPU access, picks a hardware profile from your graphics memory, writes .env, starts the stack and waits until every model server is ready.

No Docker? With Python 3.11 or later: pip install -e ".[dev]", then smriti --data-dir data serve --seed. It starts on http://127.0.0.1:8000 with the demo seeded.

2. Ask a question

Open the app. Under Viewing as, pick a person: the demo directory has people with different roles. Ask:

What is the period for submitting the performance guarantee under clause 16.1?

You get an answer with numbered citations, the steps Smriti took, and a verification score. Open a citation to see the passage it came from.

3. Ask it as of a date

Ask the same question as of an earlier date. The answer changes to the text that applied then, because the demo includes an amendment that came into force later.

4. Switch people

Ask about a restricted document as different people. One sees it in full, one sees it with names masked, and one is told nothing relevant was found. The same holds for every agent, workflow and integration.

5. Build an agent

Open Agents, start from a template, and use Try it to run it before saving. Then open Start from a workflow and run the sign-off template to see a human approval step.

6. Put it on a page

As a knowledge manager, publish an agent, open Agents → Integrations, add a website widget for this address, and press Try it on this page.

Every document in the demo is synthetic. To use your own documents, roles and sources, see Install and deploy.
