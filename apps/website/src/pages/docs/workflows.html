Workflows

A workflow is an agent built as a graph of steps. Open Agents → New agent, choose Workflow and draw it on the canvas, or start from a template under Start from a workflow. It is saved, shared, scheduled, given API keys and chatted with like any other agent.

Steps

StepWhat it doesOutputs
StartEvery run begins here with query and chat_history.one
AI agentA classic, agentic or research agent on a templated prompt. Its cited answer goes into the output variable and last.one
If / elseChecks conditions in order and follows the first that is true.one per condition, plus else
Set stateSets variables from expressions.one
CodePython in the sandbox. Variables are in a dict called state; print JSON on the last line to return a value.one
Human approvalPauses until the runner approves or declines.approved, declined
LoopOne agent prompt per list item (up to 20), collecting [{item, answer}].one
EndIts template becomes the answer.none
NoteA comment. Never runs.none

Every step also writes its result to node_<id>. On the canvas, drag a step to move it, drag from an output port onto another step to connect, click to edit, and press Delete to remove the selection.

Templates and expressions

Prompts, approval messages and End outputs are templates: Release this answer?\n\n{{ draft }}. Conditions and Set state take expressions:

len(answer) > 0 and contains(answer, 'clause')
float(amount) * 0.05
[strip(q) for q in split(query, ';')]
join(pluck(answers, 'answer'), '\n\n')
'urgent' if matches(lower(query), 'today|immediately') else 'normal'

The language is a whitelisted subset of Python expressions, parsed and walked by Smriti, never passed to eval. Allowed: literals, variables, arithmetic, comparisons, and/or/not, in, indexing, conditional expressions, simple list comprehensions, and the functions abs bool contains default float int join json keys len lower matches max min number pluck round split startswith str strip upper. Anything else is rejected when the workflow is saved.

Guarantees

  • Every agent step acts as the person running the workflow, masks personal data and verifies its answer.
  • Citations from all steps are renumbered into one list, and the final answer is scored against them.
  • A Human approval step, or a tool action inside an agent step that needs approval, pauses the whole run. Inside a Loop, such actions are skipped and recorded.
  • A run stops after 50 steps. Errors end the run with an answer naming the failing step.
  • Saving validates the graph: one Start, at least one End, every output connected, every step reachable, nothing into Start, valid names and safe expressions.

API

Workflows are agents with "kind": "workflow" and a graph:

{
  "name": "Sign-off flow",
  "kind": "workflow",
  "graph": {
    "nodes": [
      {"id": "start", "type": "start"},
      {"id": "draft", "type": "agent", "data": {"kind": "research", "prompt": "{{ query }}", "output": "draft"}},
      {"id": "ok", "type": "approval", "data": {"message": "Release?\n\n{{ draft }}"}},
      {"id": "yes", "type": "end", "data": {"output": "{{ draft }}"}},
      {"id": "no", "type": "end", "data": {"output": "Held back."}}
    ],
    "edges": [
      {"source": "start", "target": "draft"},
      {"source": "draft", "target": "ok"},
      {"source": "ok", "target": "yes", "handle": "approved"},
      {"source": "ok", "target": "no", "handle": "declined"}
    ]
  }
}

Run it with POST /api/agents/{id}/chat, or try an unsaved graph with POST /api/agents/preview. A paused run returns status: awaiting_approval and a run_id; continue with POST /api/runs/{run_id}/approve?approve=true.
