Smriti documentation

Smriti is open-source institutional memory. It reads your documents and the sites and systems you depend on, keeps every version, and answers with citations it has checked. Agents and workflows built on it act as the person asking, and everything runs on hardware you control.

Quickstart →Install, open the demo and ask your first question in five minutes. Install and deploy →Hardware profiles, configuration, scaling and offline installs. Agents and tools →Build assistants with instructions, sources, tools and approvals. Workflows →Chain agents, conditions, code, loops and human sign-off. Integrations →Website widget, Slack, Telegram and Discord. API, MCP and CLI →REST, OpenAI-compatible endpoints, MCP and the command line.

What Smriti is for

Organisations run on documents that change: policies, contracts, manuals, regulations, orders. People need the version that applies, need to see only what they're allowed to, and need to trust the answer enough to act on it. Smriti is built around those three needs:

  • Verified answers. Every sentence is checked against the passage it cites, numbers included. Answers that fail are replaced by a verified extract, or Smriti says what is missing.
  • Access that holds. Permissions are checked during search and again before display, and every agent, workflow and integration acts as the person asking.
  • Versions and amendments. Smriti knows which document supersedes or amends which, and can answer "as of" any date.
