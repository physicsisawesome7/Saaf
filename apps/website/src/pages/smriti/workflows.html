Workflows

Draw the process. Keep the guarantees.

Some work is more than one question. A workflow chains agents, conditions, variables, code and human sign-off into a single run on a visual canvas. Every agent step still acts as the person running it, cites its sources and masks personal data.

Example

Answer, then a person signs off.

A research agent drafts a cited answer. If it found one, the run pauses for a reviewer. Approved, it is released; declined, it is held back. No answer, and the asker is told so. It is one of three templates you can start from.

Steps

Nine building blocks.

StepWhat it does
StartEvery run begins here with the question and the chat history.
AI agentRuns a classic, agentic or research agent on a templated prompt, with its own tools and instructions. Writes its cited answer to a variable.
If / elseChecks conditions in order and follows the first that is true, or the else branch.
Set stateSets variables from expressions, without calling a model.
CodeRuns Python in a sandbox with no network, reading the workflow's variables and returning a value.
Human approvalPauses until the person running the workflow approves or declines, and branches on the answer.
LoopRuns one agent prompt for each item in a list and collects the answers.
EndRenders the final answer from a template.
NoteA comment for the people reading the workflow.
Safe by construction

What still holds inside a workflow.

No eval, anywhere

Conditions and templates use a small expression language that Smriti parses itself. Attribute access, imports and unknown functions are rejected when the workflow is saved, not when it runs.

Approvals pause everything

A human approval step pauses the run, and so does a tool action inside an agent step that needs approval. Only the person who started the run can approve it.

Bounded and explained

A run stops after 50 steps, so a loop back through a condition can't run forever. Any failure ends the run with an answer that names the step that failed and why.

Validated before it can run

Saving checks the graph: exactly one start, at least one end, every output connected, every step reachable, valid variable names and safe expressions. Errors read like "'If / else' (else) is not connected to a next step".
