Smriti is open source under Apache-2.0. These pages get you from nothing to a running system and explain the ideas you'll meet. The complete, versioned reference lives with the code on GitHub.

Install

With Docker and a GPU (or none), one command starts everything: the model server, embeddings and reranker, PostgreSQL, a vector store, the API and a crawler. The installer detects your card and picks a profile for 6, 12, 16 or 24 GB, or CPU only.

git clone https://github.com/physicsisawesome7/smriti && cd smriti
./install.sh          # Linux, WSL2, macOS
# Windows: powershell -ExecutionPolicy Bypass -File install.ps1

For development, or without Docker, Python 3.11 or later is enough:

pip install -e ".[dev]"
smriti --data-dir data serve --seed     # http://127.0.0.1:8000
pytest -q                               # unit tests and release gates

Everything is configured in one .env file: models, memory split, ports, authentication and which tenant pack to load. Packs (documents, roles and sources) are mounted from a folder, so changing them needs no rebuild.

A five-minute tour

The demo tenant is seeded on first start. Every document in it is synthetic.

  1. Open the app, choose a person under Viewing as, and ask about a clause. Note the citations and the verification score.
  2. Ask the same question as of an earlier date and watch the answer switch to the text in force then.
  3. Switch people and ask about a restricted document: one person sees it, another sees it with names masked, a third is told nothing was found.
  4. Open Agents, start from a template, and try it in the side panel before saving.
  5. Open Agents → Integrations, create a website widget for this address, and press Try it on this page.

Concepts

  • Tenant and pack. An organisation's documents, roles, sources, glossary and skills, loaded as a pack.
  • Principal. The person asking, with roles and grants (view, upload, curate, administer, audit). Every search, tool and answer is filtered to them.
  • Versions. Documents supersede and amend each other. Retrieval follows the graph to the text in force on the date asked.
  • Verification. Each sentence of an answer is matched to the passage it cites. Failing answers are replaced by a verified extract or withheld.
  • Masking. Personal data is masked by role and category, before models and external tools. Built on Saaf.
  • Ingestion and watch. Sources are crawled or pulled on a schedule. Changes produce a "what changed" note and an impact list of documents that cite the changed text.
  • Audit. A hash-chained log of answers, tool calls, approvals and access decisions.

Agents and workflows

An agent is a saved assistant: instructions, sources, tools, approval policy, sharing and an optional schedule. Kinds are classic (cited lookup), agentic (a tool loop), research (verified sub-questions merged into a report) and workflow (a graph of steps). See Agents and Workflows.

Workflow templates use {{ expression }}; conditions use the same safe expression language:

len(answer) > 0 and contains(answer, 'clause')
[strip(q) for q in split(query, ';')]
join(pluck(answers, 'answer'), '\n\n')

API

EndpointUse
POST /api/ask, /api/ask/streamAsk the memory directly, with citations and verification.
GET/POST /api/agentsList and create agents and workflows.
POST /api/agents/{id}/chatRun an agent, streamed or not. A paused run returns a run_id.
POST /api/runs/{id}/approveApprove or decline a paused action.
POST /v1/chat/completionsOpenAI-compatible, with model agent/<id> and an agent key.
GET/POST /api/channelsWidget and chat-app integrations.
GET /api/agents/catalogKinds, tools, workflow steps, templates and functions.
