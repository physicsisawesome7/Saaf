Agent Skills is now an open standard. Here's what it means for security

Lalit Shukla
9 Nov 2026 · Essay · 3 min read
AgentsSkillsSecurity

Skills are how agents learn to do specific jobs: a folder of instructions, scripts and resources an agent loads when it needs them. They are now governed like infrastructure. That's good news, and a reason to treat them with the same care as any other dependency.

What happened

On 22 October 2026, Anthropic announced it was donating Agent Skills, the open standard it published in December 2025, to the Agentic AI Foundation (AAIF), the Linux Foundation project it co-founded with Block and OpenAI, which already hosts the Model Context Protocol. The donation covers the name, the GitHub organisation and the agentskills.io site.

Anthropic's announcement gives a sense of scale: more than 70 agent platforms have adopted the format, including ChatGPT, Cursor, GitHub Copilot and VS Code, with around a million skills published and nearly 280 million installs. Maintainers from several companies look after the standard, and the proposed roadmap includes versioned releases, a formal proposal process, and security guidance for people who write and install skills.

Why a neutral standard matters

A skill written once now runs across many agents, so teams can package their own know-how, such as how to file an expense, review a contract or deploy a service, without rewriting it for each tool. Neutral governance makes it safer to build on: no single vendor can change the format under you, and security guidance can be agreed in the open.

Skills are a supply chain

The same portability that makes skills useful makes them a supply-chain risk. A skill is code and instructions from someone else, running with your agent's access to your files, tokens and network. Reports of agents reading planted instruction files, such as a malicious AGENTS.md left where an agent will find it, show how little it takes. Package ecosystems learned this over a decade. Agent ecosystems are learning it in months.

Five practices to adopt now

  1. Review before install. Read a skill's instructions and scripts the way you'd read a new dependency. Prefer skills from sources you can identify, and pin the version you reviewed.
  2. Grant what it declares, nothing more. A skill that summarises documents doesn't need email or the network. Give each skill the narrowest tools, data and destinations it needs, as we argued in Least privilege for agent skills.
  3. Run it in a box. Execute skill scripts in a sandbox with no ambient credentials, a read-only file system where possible, and outbound traffic through one controlled proxy.
  4. Require approval for anything irreversible. Sending, paying, deleting and posting should wait for a person, and always do once the agent has read untrusted content. See Prompt injection, explained.
  5. Log every decision. Which skill ran, which tools it called with which arguments, what was approved and by whom. When something goes wrong, the log is how you find out what happened.

None of this needs to wait for the standard's security guidance. In Smriti, agents' skills and tools run with their own role checks, code runs in a sandbox with no network, writes need approval, and every call lands in a hash-chained audit log.
