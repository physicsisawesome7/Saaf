Tools & integrations

Connect what agents use. Reach people where they work.

Tools give agents the ability to look things up and act. Integrations put those agents in front of people, in a web page or a chat app. Both come with the same rule: nothing an agent does or says goes beyond what the person behind it may see and do.

Connected tools

Bring your own systems.

REST APIs

Import operations from an OpenAPI spec, or list them by hand. Write operations stay hidden until you allow them, and then always need approval. Bearer, header, basic or query-key auth.

MCP servers

Every tool on a server, over streamable HTTP or SSE. Tools not marked read-only need approval. Smriti is also an MCP server itself, so other assistants can search its memory.

Databases

Read-only SELECT in a read-only transaction, with a row cap. Add table notes so the model writes good SQL.

Every connected tool lists the roles that may use it and how sensitive its results are. Credentials are encrypted at rest and never returned by the API. Saving a tool reads its actions from the target, so you see exactly what agents can call.

Integrations

An agent in your intranet, Slack, Telegram or Discord.

Website widget

One script tag adds a chat bubble with streamed, cited answers. It renders in its own shadow root, so your page's styles can't break it, and it only runs on the sites you allow.

<script src="https://smriti.example/widget.js"
  data-smriti-widget="wg_…" async></script>

Slack

Mention the app in a channel or message it directly. Answers arrive in the thread, and a thread is one conversation. Approvals are buttons only the asker can press.

Telegram

A bot for field staff. Paste the token from BotFather and connect the webhook from Smriti. Each chat continues one conversation.

Discord

An app with an /ask command. Every interaction is verified with Discord's signature before Smriti reads it.

Identity and safety

Every integration answers as someone.

A stated identity

Its creator; the signed-in user of your site, through a short-lived signed token; or chat users mapped to people by an administrator. Unmapped people are refused.

Masked on the way out

Chat apps store every message on their own servers, so personal data in replies sent there is masked by default.

Classified stays home

An answer citing documents above the integration's limit is replaced by a link back to Smriti, and the event is audited.

Verified requests

Slack signing secrets, Telegram secret tokens, Discord Ed25519 signatures, and an origin allow-list with rate limits for the widget.

Ingestion

Where Smriti's memory comes from.

Multi-page website crawls, single links, file uploads, REST and JSON APIs, SQL databases, MCP servers, RSS feeds and sitemaps, and server folders. Each source has a test-connection dry run, its own access and schedule, and background jobs you can watch and cancel. Requests go through an egress guard, credentials are encrypted, and SQL is read-only.
